Antes de empezar

  • No es una lista universal. Este baseline es un punto de partida para un diagnóstico y una implementación adaptada a cada organización, no una configuración que todos deban aplicar igual.
  • Cuentas de emergencia: Usa al menos dos, exclusivamente cloud (dominio .onmicrosoft.com), excluidas de las políticas de Acceso Condicional que puedan impedir su acceso.
  • Licenciamiento: Las etiquetas de licencia son orientativas. No reemplazan la validación previa de las licencias y funcionalidades requeridas por cada usuario incluido en el alcance.

Grupo 1 · Identidad y autenticación

Controles 01–06. Proteger identidades y métodos de autenticación.

01
Bloquear autenticación heredada
Microsoft Entra ID P1
ObjetivoCerrar protocolos legacy (IMAP, POP, SMTP, Exchange ActiveSync antiguo).
DescripciónSe restringe el uso de protocolos heredados que no admiten o no aplican adecuadamente los controles de autenticación moderna, como MFA.
Fuente: Microsoft Learn — Bloquear la autenticación heredada con acceso condicional →
02
Bloquear device code flow
Microsoft Entra ID P1
ObjetivoBloquear el flujo de código de dispositivo en los recursos incluidos en el alcance de la política.
DescripciónEl Device Code Flow (flujo de código de dispositivo) permite autenticarse en un equipo utilizando un código introducido desde otro dispositivo. Este mecanismo puede ser explotado mediante ataques de ingeniería social, en los que un atacante induce a un usuario legítimo a introducir un código que autoriza la autenticación en un dispositivo controlado por el atacante. La política busca bloquear este vector de ataque, permitiendo únicamente excepciones para escenarios legítimos previamente identificados e inventariados, como Teams Rooms o Azure CLI.
Fuente: Microsoft Learn — Bloquear flujos de autenticación con acceso condicional →
03
MFA resistente al phishing para administradores
Microsoft Entra ID P1
ObjetivoProteger las cuentas con roles privilegiados frente a ataques de phishing, robo de credenciales y secuestro de sesiones, exigiendo métodos de autenticación resistentes al phishing.
DescripciónLos métodos MFA tradicionales, como SMS, códigos OTP y notificaciones push, pueden ser vulnerables a ataques de intermediario (Adversary-in-the-Middle) o de fatiga de notificaciones (Push Fatigue). Esta política exige métodos de autenticación resistentes al phishing, como FIDO2, Windows Hello for Business o autenticación basada en certificados (CBA), que reducen significativamente el riesgo de suplantación de identidad y compromiso de cuentas privilegiadas.
Fuente: Microsoft Learn — Requerir MFA resistente al phishing para administradores →
04
MFA para todos los usuarios
Microsoft Entra ID P1
ObjetivoReducir el impacto de una credencial comprometida (ej contraseña robada) y establecer autenticación multifactor en toda la organización.
DescripciónSin una política de MFA global, las contraseñas comprometidas mediante phishing, reutilización de credenciales o ataques de Password Spraying pueden permitir el acceso directo a los recursos corporativos. Esta política exige un segundo factor de autenticación para todos los usuarios, añadiendo una capa de protección frente al uso indebido de credenciales y reduciendo el riesgo de accesos no autorizados.
Fuente: Microsoft Learn — Requerir MFA para todos los usuarios →
05
MFA para portales de administración
Microsoft Entra ID P1
ObjetivoProteger el acceso a los portales administrativos y a Azure Management, exigiendo autenticación multifactor para reducir el riesgo de accesos no autorizados al plano de administración.
DescripciónSi los portales administrativos y los recursos de Azure no están cubiertos por políticas de MFA, un atacante con credenciales comprometidas podría acceder y realizar operaciones administrativas sin una verificación adicional. Esta política establece una protección específica para el plano de administración, complementando las políticas generales de MFA y cubriendo posibles brechas de alcance.
Fuente: Microsoft Learn — Requerir MFA para portales de administración →
06
Proteger el registro de información de seguridad
Microsoft Entra ID P1
ObjetivoEvitar que un atacante con una sesión comprometida registre sus propios métodos de autenticación y establezca mecanismos de acceso persistente a la cuenta.
DescripciónSi el registro de información de seguridad no está protegido, un atacante que obtenga acceso a una sesión legítima puede registrar un método MFA bajo su control y conservar el acceso a la cuenta, incluso después de un cambio de contraseña. Esta política exige controles adicionales de autenticación para proteger el registro y la modificación de los métodos de seguridad, reduciendo el riesgo de persistencia y toma de control de las cuentas.
Fuente: Microsoft Learn — Proteger el registro de información de seguridad →

Grupo 2 · Dispositivos y aplicaciones

Controles 07–09B. Controlar dispositivos, aplicaciones y sesiones.

07
Requerir dispositivo compatible
Microsoft Entra ID P1MICROSOFT INTUNE P1
ObjetivoRestringir el acceso a los servicios de Microsoft 365 desde dispositivos administrados y que cumplan las políticas de seguridad establecidas por la organización, tanto en Windows como en macOS.
DescripciónSin controles de cumplimiento de dispositivos, un atacante con credenciales válidas podría acceder a los recursos corporativos desde equipos personales o no administrados, potencialmente sin cifrado, antivirus ni controles de seguridad. Esta política condiciona el acceso al cumplimiento de los requisitos de seguridad definidos en Microsoft Intune, reduciendo la exposición de la información corporativa y limitando el acceso a dispositivos bajo control de la organización.
Fuente: Microsoft Learn — Requerir dispositivo compatible →
08
Requerir app protection policy en móviles
Microsoft Entra ID P1MICROSOFT INTUNE P1
ObjetivoProteger la información corporativa en dispositivos móviles mediante controles sobre el acceso, la transferencia y el almacenamiento de datos dentro de las aplicaciones.
DescripciónSin políticas de protección de aplicaciones (App Protection Policies), los usuarios pueden transferir información corporativa a aplicaciones personales, guardarla en ubicaciones no administradas o acceder a ella desde dispositivos que no cumplen los requisitos de seguridad. Esta política condiciona el acceso a la aplicación de controles que restringen la copia, el almacenamiento y la transferencia de datos corporativos, manteniendo la separación entre la información personal y empresarial.
Fuente: Microsoft Learn — Requerir directiva de protección de aplicaciones →
09A
Restricciones de aplicaciones en dispositivos no administrados
Microsoft Entra ID P1
ObjetivoLimitar las operaciones disponibles al acceder a los servicios corporativos desde dispositivos no administrados, reduciendo el riesgo de fuga de información sin impedir completamente el acceso a los recursos.
DescripciónCuando se permite el acceso desde dispositivos no administrados sin restricciones, los usuarios pueden descargar, imprimir, copiar o sincronizar información corporativa en equipos que están fuera del control de la organización. Esta política permite aplicar restricciones de acceso, como habilitar únicamente el acceso desde el navegador y limitar las opciones de descarga e impresión, reduciendo la exposición de los datos corporativos.
Fuente: Microsoft Learn — Aplicar restricciones de aplicaciones →
09B
Control de persistencia de sesión del navegador
Microsoft Entra ID P1
ObjetivoControlar la permanencia de sesiones en navegadores, especialmente en dispositivos no administrados, y complementar este control con requisitos de reautenticación cuando sea necesario.
DescripciónLa configuración de sesión persistente del navegador permite controlar si los usuarios pueden mantener una sesión iniciada después de cerrar y volver a abrir el navegador. Puede deshabilitarse para reducir la persistencia en equipos no administrados. La frecuencia de inicio de sesión (Sign-in frequency) es un control distinto que determina cuándo se requiere volver a autenticarse; ambos pueden configurarse de forma complementaria según el escenario y el riesgo.
Fuente: Microsoft Learn — Control de persistencia de sesión del navegador →

Grupo 3 · Acceso externo y flujos

Controles 10A–12. Proteger invitados, ubicaciones y flujos de autenticación.

10A
MFA para invitados y usuarios externos en aplicaciones permitidas
Microsoft Entra ID P1
ObjetivoProteger el acceso de invitados y usuarios externos a los recursos corporativos, exigiendo autenticación multifactor (MFA) para las aplicaciones autorizadas y reduciendo el riesgo de compromiso de cuentas de terceros.
DescripciónSi los usuarios externos acceden a los recursos compartidos sin MFA, un atacante que comprometa una cuenta de partner o invitado podría utilizarla para acceder a la información corporativa. Esta política exige MFA para los usuarios externos, añadiendo una capa de protección frente al uso indebido de credenciales y reduciendo el riesgo de accesos no autorizados.
Fuente: Microsoft Learn — MFA para invitados y externos →
10B
Bloquear acceso de invitados y usuarios externos a aplicaciones no autorizadas
Microsoft Entra ID P1
ObjetivoRestringir el acceso de invitados y usuarios externos exclusivamente a las aplicaciones autorizadas por la organización, bloqueando el acceso a los recursos que se encuentren fuera del alcance definido.
DescripciónSi únicamente se establecen requisitos de autenticación para los invitados, estos podrían acceder a otras aplicaciones del tenant que no estén restringidas explícitamente. Esta política establece un bloqueo para las aplicaciones no autorizadas, limitando la exposición de los recursos corporativos y reduciendo el impacto potencial del compromiso de una cuenta externa.
Fuente: Microsoft Learn — Bloquear acceso de invitados a apps no permitidas →
11
Restricción de acceso por ubicación geográfica
Microsoft Entra ID P1
ObjetivoRestringir el acceso a los recursos corporativos según las ubicaciones geográficas autorizadas por la organización, reduciendo la exposición a intentos de acceso desde regiones donde no existe operación empresarial.
DescripciónSin restricciones geográficas, un atacante con credenciales comprometidas podría intentar acceder a los recursos corporativos desde cualquier ubicación del mundo, incluidas regiones donde la organización no tiene presencia ni actividad operativa. Esta política permite limitar el acceso a los países y regiones autorizados, reduciendo la superficie de exposición ante accesos sospechosos.
Fuente: Microsoft Learn — Bloqueo geográfico con acceso condicional →
12
Controlar la transferencia de autenticación (Authentication Transfer)
Microsoft Entra ID P1Preview
ObjetivoEvitar que una sesión autenticada en un dispositivo pueda transferirse a otro sin completar un nuevo proceso de autenticación, reduciendo el riesgo de uso indebido de sesiones existentes.
DescripciónAuthentication Transfer es una funcionalidad legítima que facilita determinados escenarios de autenticación entre dispositivos, por ejemplo, iniciar un proceso en un equipo y completarlo en un móvil. Si no existe una necesidad empresarial, la organización puede restringir este flujo como medida de hardening. Antes de bloquearlo, se recomienda evaluar el impacto, identificar escenarios de uso legítimos y probar la política en modo de solo informe.
Fuente: Microsoft Learn — Bloquear transferencia de autenticación →

Grupo 4 · Protección avanzada

Controles 13–15B. 14–15B requieren registro MFA previo; 13 es protección de tokens y no es una política de riesgo.

13
Protección contra reutilización de tokens de sesión
Microsoft Entra ID P1
ObjetivoReducir el riesgo de robo y reutilización de tokens de autenticación, vinculándolos al dispositivo legítimo para dificultar su uso desde equipos no autorizados.
DescripciónCuando los tokens no están vinculados al dispositivo, un atacante que los obtenga mediante malware, infostealers u otros mecanismos podría intentar reutilizarlos desde otro equipo. Token Protection aplica vinculación criptográfica entre determinados tokens de sesión y el dispositivo en escenarios compatibles, dificultando que un token sustraído pueda reutilizarse desde otro equipo. Su disponibilidad depende de plataformas, aplicaciones y recursos compatibles; no debe asumirse que protege todos los tokens o flujos. Antes de habilitarla, validar el alcance soportado, las exclusiones y el impacto en el tenant. No sustituye MFA, controles de dispositivo ni otras medidas de seguridad.
Fuente: Microsoft Learn — Token protection en acceso condicional →
14
Requerir MFA ante riesgo elevado de inicio de sesión
Microsoft Entra ID P2
ObjetivoExigir una verificación adicional de identidad cuando Microsoft Entra ID detecte un inicio de sesión con riesgo elevado, reduciendo la probabilidad de acceso no autorizado ante posibles intentos de suplantación o compromiso de credenciales.
DescripciónUn inicio de sesión con riesgo elevado puede reflejar señales asociadas a un posible compromiso, como propiedades de autenticación anómalas o actividad sospechosa. Mediante una política de Acceso Condicional basada en Sign-in Risk, se puede exigir MFA o una autenticación de mayor resistencia ante riesgo medio y alto, según los métodos disponibles y el escenario de la organización. Sign-in frequency = Every time puede configurarse como control adicional de sesión, pero no debe aplicarse automáticamente como requisito universal: valorar el riesgo, los métodos passwordless, la experiencia del usuario y el potencial de fatiga de autenticación. La configuración debe contemplar los métodos de autenticación utilizados, incluidos los escenarios passwordless.
Fuente: Microsoft Learn — Riesgo de inicio de sesión →
15A
Bloquear cuentas privilegiadas con riesgo alto
Microsoft Entra ID P2
ObjetivoImpedir el acceso de cuentas privilegiadas identificadas con riesgo alto hasta que se realice una revisión y validación por parte de otro administrador, reduciendo la posibilidad de que una identidad comprometida mantenga acceso a recursos críticos.
DescripciónEl compromiso de una cuenta privilegiada puede permitir el acceso a información sensible, la modificación de controles de seguridad o la creación de nuevas identidades privilegiadas. Para estas cuentas, se recomienda configurar una política independiente de User Risk alto y evaluar el control Require risk remediation, que incorpora controles de autenticación y frecuencia de inicio de sesión para el proceso de remediación, o bloquear el acceso según el diseño de seguridad. La revisión por otro administrador, la investigación y la autorización de recuperación son procedimientos operacionales externos a la política y deben definirse por la organización.
Fuente: Microsoft Learn — Riesgo de usuario →
15B
Bloquear inicios de sesión de alto riesgo en cuentas privilegiadas
Microsoft Entra ID P2
ObjetivoBloquear el acceso de cuentas privilegiadas cuando el inicio de sesión sea identificado con riesgo alto, evitando que una autenticación previamente superada sea suficiente para acceder a recursos críticos y estableciendo un proceso de revisión antes de restablecer el acceso.
DescripciónUn inicio de sesión de alto riesgo puede indicar señales de compromiso, incluso si se ha completado la autenticación, incluido MFA. Para cuentas privilegiadas, se puede aplicar una política basada en Sign-in Risk que bloquee el acceso cuando el riesgo sea alto. El desbloqueo y la recuperación deben seguir un proceso de revisión definido por la organización.
Fuente: Microsoft Learn — Bloquear riesgo de inicio de sesión alto en cuentas privilegiadas →
